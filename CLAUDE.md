## Project Overview

Life Planner is a Flutter app that combines personal productivity with project management. It features:
- **Task Management** with three distinct types: distractions (habits to avoid), practices (habits to build with streak tracking), and goals (objectives with milestones/subtasks)
- **Project Visualization** with Gantt charts, Kanban boards, and burndown charts for tracking project progress
- **Mind Mapping** for visual planning with linkable task nodes
- **Time Blocking** with daily and weekly calendar views for scheduling tasks
- **Dashboard** with customizable widgets showing stats, streaks, deadlines, and scheduled time blocks

## Architecture

### State Management Pattern
The app uses Provider with ChangeNotifier for reactive state. Providers are injected at app root via `MultiProvider` in `main.dart`:

- **TaskProvider** - CRUD operations for tasks, subtasks, milestones; manages Kanban status, dependencies, and project assignments
- **MindMapProvider** - Manages mind map nodes and their connections
- **ProjectProvider** - Manages projects and selected project state for visualizations
- **TimeBlockProvider** - Manages scheduled time blocks for the time blocking feature

All providers depend on `StorageService` which is injected via constructor.

### Data Persistence
Uses Hive (NoSQL) for local storage with separate boxes:
- `tasks` - Stores `Task` objects (typeId: 1)
- `mindMap` - Stores `MindMapNode` objects (typeId: 2)
- `projects` - Stores `Project` objects (typeId: 11)
- `timeBlocks` - Stores `TimeBlock` objects (typeId: 12)
- `dashboardConfig` - Stores `DashboardConfig` singleton (typeId: 14)

Models extend `HiveObject` to enable `save()` method calls. The `StorageService.init()` must be called before `runApp()` to register adapters and open boxes. On schema mismatch, boxes are automatically deleted and recreated.

### Code Generation Files
`*.g.dart` files are auto-generated by `build_runner` and should not be manually edited. They are referenced via `part` directive in model files. When adding new `@HiveField` annotations or modifying Hive models, always run build_runner.

### Task Type System
The `TaskType` enum drives different UI behaviors and fields:
- `distraction` - Tasks to eliminate with `replacementBehavior`, `commonTriggers`, `costImpact`, and `streakCount` (days avoided)
- `practice` - Daily habits with `progressMetric`, `resourcesNeeded`, `reflectionPrompt`, and `streakCount` (days completed)
- `goal` - Long-term objectives with `milestones`, `subtasks`, `whyPurpose`, `successCriteria`, and `relatedHabits`

All task types support optional fields: `priority`, `frequency`, `deadline`, `category`, `reminderTime`, `timeEstimate`, `projectId`, `dependencies`, `kanbanStatus`, and `startDate`.

### Project Visualization System
Projects organize tasks for Gantt, Kanban, and Burndown visualizations:

1. **Tasks vs Subtasks**: In the visualizer, **subtasks** are the primary actionable items displayed in all three views. Parent tasks act as containers that group related subtasks.

2. **Kanban Workflow**: Tasks/subtasks flow through `KanbanStatus` enum: `backlog` → `todo` → `inProgress` → `review` → `done`. Moving to "done" auto-completes the task.

3. **Gantt Timeline**: Uses `effectiveStartDate` (startDate or createdAt) and `effectiveEndDate` (deadline or startDate+1 day). Dependencies are shown as arrows.

4. **Burndown Chart**: Tracks `remainingTimeEstimate` over time. Requires `timeEstimate` (in minutes) on tasks/subtasks for accuracy.

5. **Auto-completion**: When all subtasks of a goal are completed, the parent task auto-completes (and vice versa for uncompleting).

### Recurring Task Reset
On app startup, `main.dart` calls `TaskProvider.resetRecurringTasks()` which checks all completed tasks with `frequency` set (daily, weekly, monthly) and resets their completion status if the recurrence period has passed.

### Time Blocking
`TimeBlock` objects represent scheduled calendar entries:
- Can link to tasks (`linkedTaskId`) or subtasks (`linkedSubtaskId`)
- Displayed in daily or weekly views based on `DashboardConfig.defaultToWeeklyView`
- Time slots are configurable via `DashboardConfig.timeSlotInterval` (15/30/60 minutes)
- Working hours set by `dayStartHour` and `dayEndHour` in config

### Mind Map Linking
`MindMapNode.linkedTaskId` creates a reference to a task's ID, enabling bidirectional navigation between visual planning (mind map) and actionable items (tasks).

### Navigation Structure
The app uses bottom navigation (Material 3 `NavigationBar`) with four main screens:
- **Home (Dashboard)** - Customizable dashboard with time blocks, daily tasks, stats, streaks, projects, and deadlines
- **Planner** - Task management interface organized by task type (distractions, practices, goals)
- **Visualizer** - Project selector with tabs for Gantt chart, Kanban board, and Burndown chart
- **Settings** - App configuration including dashboard widget toggles and time block preferences

Navigation state is managed in `HomeScreen` using a `StatefulWidget` with index-based screen switching.

## Important Patterns

### Adding New Hive Fields
1. Add `@HiveField(N)` annotation to model (use next available field ID)
2. Run `dart run build_runner build --delete-conflicting-outputs`
3. Note: Changing existing field IDs or types will cause schema mismatch (auto-handled by deleting boxes)

### Provider Usage
Always access providers via `context.read<Provider>()` for one-time operations or `context.watch<Provider>()` / `Consumer<Provider>` for reactive updates.

### Task Dependencies
Use `TaskProvider.addDependency()` and `TaskProvider.getDependencies()` to manage task relationships. Check `TaskProvider.areDependenciesComplete()` before allowing task start.
